# Project Memory

## Product

Minimalist.chat is a room-centered communication product. Its current public positioning emphasizes calm, organized group chat with catch-up digests, focus modes, decisions, action items, scheduled messages, templates, roles, and offline-first reading. The broader app includes collaborative room features such as documents, whiteboards, events, tasks, calls, search, moderation, and AI-assisted workflows.

Sources: [[10 Product/Current/Current Product Overview|Current Product Overview]], [[20 Research/Claude Feature Research and Implementation Plan|Feature Research]].

## Technical shape

- React 19 + Vite 6 frontend.
- Firebase Auth, Realtime Database, Functions, Hosting, and Storage-oriented workflows.
- Capacitor Android/iOS packaging.
- Express server path plus Socket.IO dependency.
- Stripe billing integration.
- Node.js 22 or newer is required by `package.json`.

The repository is in an active React/Vite migration and has substantial existing local changes. Preserve unrelated work and avoid broad rewrites.

## Security and AI invariants

- The public client must never call raw Ollama directly.
- Browser AI requests go through the authenticated Firebase `aiGateway`.
- The gateway enforces identity, room access, quota/“Bananas,” abuse controls, and audit logging before calling the protected bridge.
- The bridge requires a bearer token and must remain private; fail closed when bridge identity/configuration is invalid.
- Remote Analysis uses a separate read-only Windows agent, Cloudflare hostname, and exact-owner Access policy; it never exposes desktop administration controls or falls back to controlling the client computer.
- Do not claim end-to-end encryption unless the actual implementation and threat model support that claim.

Sources: [[40 Operations/Protected Ollama Public Gateway|Protected Ollama Public Gateway]], [[40 Operations/Remote Analysis Access|Remote Analysis Access]].

- 2026-07-15 — The repository's optional website text-AI router assigns active slots 1–10 to the protected local PC through Ollama, slots 11–50 to Cloudflare Workers AI with `@cf/qwen/qwen3-30b-a3b-fp8`, and slots 51–90 to Groq with `openai/gpt-oss-20b`. Request 91 and later overflow requests enter a durable FIFO queue and remain there until processed, explicitly cancelled by their owner, or permanently failed; capacity alone does not expire accepted work. Submission returns HTTP 202 rather than holding the request connection open, and the client follows completion through an owner-only realtime status/result mirror with authenticated polling recovery. Admission is bounded at 10,000 unfinished routed requests globally and 1,000 per owner, both above the 500-job stress target; accepted work is never evicted. A random ABA-safe reservation stays held across direct execution, queueing, running, and retries, and terminal job/admission markers plus a one-minute sweeper make release crash-recoverable. Banana receipts are atomic `charged`/`refunded` tombstones keyed to the durable job, so quota rollover cannot double-charge or replay a refunded request. Transient failures back off and exclude the failed provider without bypassing the FIFO head; incomplete provider configuration fails before charge and terminally refunds previously queued work. Terminal records may be retained for up to 24 hours. The no-cost two-client RTDB contention harness accepts 500 unique jobs plus 50 duplicate submissions, recovers interrupted claims, drains every job, and finishes with zero reservations and zero external AI calls; it is not a 500-socket load test. These hosted IDs are overflow implementations, not selectable client profile IDs or Ollama tags.
